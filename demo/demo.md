# 譜面生成デモ

このディレクトリのWAVファイルをゲームの「曲を選ぶ」から読み込むと、`src/audio.ts` の譜面生成がどの情報に反応するかを短い音で比較できます。音はすべてSoXで合成しており、音源の再生成方法は末尾にあります。

## 先に知っておくこと

このゲームの譜面は、音程を音符へ変換したものではありません。主に次の2つを組み合わせた「叩く時刻の列」です。

1. **onset**: 直前より低・中・高域の音量が急に増えた時刻。実際に音が鳴り始めた場所を表します。
2. **BPMグリッド**: 推定BPMから作る等間隔の目盛り。譜面の周期的な骨格になります。

BPMグリッドの近く（最大で前後100 ms）にonsetがあれば、判定点はグリッドそのものではなく実際の発音時刻へ寄ります。格子外でも十分に強いonsetは、既存の点から0.24秒以上離れていれば追加されます。一方、通常の主拍は0.48秒以上の操作間隔になるよう、高BPMでは何拍かおきに間引かれます。

画面の `RHYTHM POINTS` は判定点数、`BEAT GRID` はBPMグリッドを使った譜面、`ONSET` はフォールバック譜面を意味します。BPM推定には倍テンポ・半分テンポの曖昧さがあるため、表示BPMは下記の期待値と異なることがあります。比較するときは、表示値だけでなくリズムレールの線が実際の発音へ合っているかも確認してください。

現在の実装をChromiumで解析した結果は次のとおりです。WAVは非圧縮PCMなので、別のWeb Audio API対応ブラウザでもほぼ同じ時刻になります。

| 音源 | 判定点数 | BPM表示 | 方式 |
| --- | ---: | ---: | --- |
| `01-steady-120bpm.wav` | 19 | 120 | `BEAT GRID` |
| `02-humanized-120bpm.wav` | 19 | 120 | `BEAT GRID` |
| `03-syncopation-100bpm.wav` | 20 | 100 | `BEAT GRID` |
| `04-fast-180bpm.wav` | 28 | 90 | `BEAT GRID` |
| `05-rest-in-the-middle.wav` | 14 | 120 | `BEAT GRID` |
| `06-silence-fallback.wav` | 6 | 134（点間隔からの概算） | `ONSET` |

## デモ音源

### 1. `01-steady-120bpm.wav` — 一定テンポの基本

- **入力音**: 0.5秒から9.5秒まで、0.5秒間隔（120 BPM）で鳴る低いクリック。4拍ごとの音を少し強くしています。
- **期待する譜面**: おおむね各クリックに判定点が並ぶ `BEAT GRID` 譜面。
- **分かること**: `60 / 120 = 0.5`秒なので、推定BPMのグリッドとonsetが重なります。周期の骨格と実音が同じ最も単純な例です。

クリック時刻: `0.500, 1.000, 1.500, ... , 9.500` 秒

### 2. `02-humanized-120bpm.wav` — グリッドから実音へのスナップ

- **入力音**: 基本は120 BPMですが、クリックを基準位置から最大45 ms前後させています。
- **期待する譜面**: 密度は1番とほぼ同じまま、判定点の時刻が0.5秒刻みではなく各クリックの時刻へ寄る `BEAT GRID` 譜面。
- **分かること**: BPMグリッドは「拍の所属」を決めますが、最終的に叩く位置は近傍onsetです。人間の演奏にある小さな前ノリ・後ノリを、完全な機械グリッドへ矯正しません。

クリック時刻: `0.500, 1.045, 1.478, 2.020, 2.500, 3.035, 3.485, 4.030, ...` 秒

### 3. `03-syncopation-100bpm.wav` — 強い格子外onsetの追加

- **入力音**: 0.6秒間隔（100 BPM）の低い主拍に加え、1.4、3.8、6.2、8.6秒へ高く強い音を置いています。追加音は前後の主拍から0.3秒離れています。
- **期待する譜面**: 主拍に加え、4個の高い音にも判定点が追加される `BEAT GRID` 譜面。
- **分かること**: 強い発音がグリッドの中央にあれば、裏拍やシンコペーションとして追加できます。周波数が高いから追加されるのではなく、急な立ち上がりが十分に強く、既存点との間隔が0.24秒以上あるためです。

主拍: `0.500, 1.100, 1.700, ... , 9.500` 秒  
追加音: `1.400, 3.800, 6.200, 8.600` 秒

### 4. `04-fast-180bpm.wav` — 高速な強いonsetと密度制限の境界

- **入力音**: 約0.333秒間隔（180 BPM）の均一な低いクリック。
- **実際の譜面**: BPMは半テンポの90と推定されますが、曲末余白に入る最後の1音を除いた28音が約0.333秒間隔で判定点になります。
- **分かること**: `minimumBeatGap = 0.48`秒が制限するのは、BPMグリッドの主拍とonset方式の第1フォールバックです。十分に強い格子外onsetを追加する規則は、より短い `minimumPatternGap = 0.24`秒を使います。この音源では各クリックが強いonsetなので、90 BPMの骨格の間にある音も追加されます。

したがって、0.48秒は譜面全体の絶対的な最小間隔ではありません。明瞭な裏拍やシンコペーションは約4.2回/秒まで追加でき、このデモはその境界を確認するための例です。また、180 BPMと90 BPMは同じ位置へ周期の目盛りを置けるため、BPM推定では半テンポとして解釈されることがあります。

### 5. `05-rest-in-the-middle.wav` — 休符には点を置かない

- **入力音**: 前半と後半には120 BPMのクリックがあり、4.0秒から6.0秒までは完全な無音です。
- **期待する譜面**: 前後のクリックには判定点が並び、中央の休符には判定点が置かれない譜面。
- **分かること**: グリッドが曲全体へ続いていても、近傍onsetがなく周辺RMSも小さい点は除外されます。そのため、周期だけを理由に無音部分を叩かせません。

### 6. `06-silence-fallback.wav` — 判定点不足の最終フォールバック

- **入力音**: 6秒間の完全な無音です。
- **期待する譜面**: `ONSET` と表示され、約0.82秒ごとの区間から1点ずつ、細い判定点が生成されます。
- **分かること**: onsetも有効なBPMグリッドも得られない場合、それでもゲームを開始できるよう最低限の譜面を作ります。この段階は音楽的な検出ではなく可用性のための最終手段なので、無音にも点が生じます。

このファイルは無音なので、再生機器の故障ではありません。フォールバックの限界を明示するための境界例です。

## 比較のおすすめ順

1. 1番と2番を比べ、同じテンポでも実際の発音位置が判定時刻に残ることを確認する。
2. 3番で、等間隔の骨格以外にも強い音が追加されることを確認する。
3. 4番で、0.48秒の主拍制限よりも、強い格子外onsetに使う0.24秒の制限が優先される場合を確認する。
4. 5番と6番を比べ、「明確な周期の途中にある休符は除外する」処理と、「何も検出できない曲へ最低限の点を作る」処理の違いを見る。

解析結果の `strength` はリズムレールの線幅には影響しますが、PERFECT/OKの許容幅や得点は変えません。つまり、強い音の線が太く見えても、押す難しさの時間幅は他の判定点と同じです。

## 再生・再生成

個別に聴くには、リポジトリのルートで次を実行します。

```bash
play demo/01-steady-120bpm.wav
```

全WAVファイルは `generate.sh` がSoXの `synth`、`pad`、`-m`（ミックス）を使って生成します。再生成すると同名ファイルを上書きします。

```bash
./demo/generate.sh
```
